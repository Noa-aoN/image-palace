# ADR: 画像ストレージ・CDN 戦略

- **日付**: 2026-03-17
- **ステータス**: 承認済み
- **決定者**: チーム

---

## コンテキスト

ImagePalace はユーザーごとに AI 生成画像を大量に保存・配信する。
画像の保存・配信戦略はサービスの核心であり、コスト・パフォーマンス・将来拡張性を慎重に設計する必要がある。

要件：
- AI 生成画像（PNG/WebP、512px〜1024px）を永続保存
- 世界中のユーザーへ高速配信
- 同一単語の画像はキャッシュして OpenAI API コストを削減
- 将来的なリサイズ・最適化（WebP 変換、サムネイル生成）に対応可能なこと

---

## 検討した選択肢

### A. S3 直配信
- **メリット**: シンプル、追加サービス不要
- **デメリット**: レイテンシが高い（特に海外ユーザー）、S3 の GET リクエスト料金がかさむ、リサイズ・最適化が困難

### B. S3 + CloudFront
- **メリット**: AWS エコシステム内で完結、Lambda@Edge でリサイズ可能、キャッシュ設定が細かく制御可能
- **デメリット**: CloudFront の設定が複雑、AWS の学習コスト

### C. S3 + Cloudflare Images
- **メリット**: Cloudflare の CDN ネットワーク（世界最大級）、自動 WebP 変換・リサイズが組み込み
- **デメリット**: Cloudflare Images は有料（$5/月〜）、S3 との二重管理

### D. Cloudinary / imgix
- **メリット**: 画像最適化に特化したサービス、SDK が充実
- **デメリット**: ベンダーロックイン、コストが高め

---

## 決定

**S3 をストレージとして使用し、CDN は CloudFront または Cloudflare Images を採用する**

- **S3 直配信は禁止**（パフォーマンス・コスト両面で不適）
- MVP は CloudFront（設定コストが低く AWS 内で完結）を優先検討
- Cloudflare DNS を使っている場合は Cloudflare Images も有力な選択肢

---

## 理由

1. **画像が核心サービス**: ImagePalace において画像の表示速度は UX に直結する。CDN は必須
2. **コスト最適化**: CDN キャッシュにより S3 GET リクエスト数を大幅削減できる
3. **リサイズ・最適化**: カード表示用サムネイル、WebP 変換など将来機能に対応できる
4. **S3 の柔軟性**: ストレージを S3 に統一することで、CDN レイヤーを後から変更しやすい

---

## キャッシュ戦略

```
ユーザーリクエスト
  → Rails (DB で同一単語チェック)
    → キャッシュあり: S3 の既存画像 URL を返す
    → キャッシュなし: OpenAI Images API で生成 → S3 保存 → URL を DB に記録
  → フロントエンドが CDN URL 経由で画像を表示
```

- 同一単語の画像は DB にキャッシュして OpenAI API を再呼び出ししない
- CDN の TTL は長め（画像は更新されない前提）に設定

---

## 結果・影響

- `CLAUDE.md` の Infra 行に CloudFront or Cloudflare Images を明記
- バックエンドは `ActiveStorage` + S3 アダプタを使用（直接 AWS SDK は使わない）
- CDN URL を環境変数 `CDN_BASE_URL` で管理し、コードに直書きしない
- `docs/OS.md` の画像フロー図を更新すること（別途）
