# 失敗した画像の作り直しに、種類と上限を置く

2026-08-11

## 何が問題だったか

失敗からの作り直しは無料にしてある。渡せていないものに課金しない、という判断で、これ自体は変えない。
ただし**無料であること**と**何度でも押せること**を分けていなかった。

- 押すたびに供給側へ1回問い合わせが飛び、そのたびにこちらの原価が出る
- 上限が無い。速度の制限（`item_retry` 20回/分/IP）はあるが、総量の制限は無い
- つまり1人が押し続けるだけで、こちらの費用は伸び続ける

さらに、**押しても直らない失敗**がある。

- 方針に触れた入力（content policy）
- 入力から絵を決められない（400）

これらは同じ入力なら必ず同じ結果になる。押させると、失敗すると分かっている呼び出しに毎回お金がかかり、
利用者は直らないものを押し続けることになる。どちらにとっても損しかない。

スペースのポイントは作り直しでも毎回クレジットを取るので、こちらはさらに悪く、
**必ず失敗すると分かっているものに課金**していた。

## 決めたこと

失敗の種類を残し、押す前に2つを判断する。

### 1. そもそも押して直るのか

`ImageGenerationErrorHandling#failure_kind` で4つに分け、`metadata.generation_failure_kind` に残す。

| 種類 | 意味 | 扱い |
|---|---|---|
| `content_policy` | 方針に触れた | 入力を変えるまで通さない |
| `invalid_input` | 入力から絵を決められない | 入力を変えるまで通さない |
| `quota` | 供給側の枯渇 | 続いている間は通さない（利用者には直せない） |
| `temporary` | 通信・混雑 | 通す |

### 2. 何度まで無料か

`temporary` は押す意味がある。ただし4回続けて失敗するなら、それはもう一時的ではない。
無料は3回（`FREE_RETRY_LIMIT`）まで。以降は通すが、クレジットを使う。
出来上がったら回数は0に戻す。

## 「入力を変えた」をどう見るか

指示が渡されたかでは判定できない。

- 作り直しパネルは、指示欄が空でも `custom_prompt: ""` を必ず送る
- 単語や情景プロンプトの書き換えは別の口（`PATCH /items/:id`）から入る

なので、**実際に供給側へ渡る文字列**を突き合わせる（`Images::PromptFingerprint`）。
生成のたびに指紋を `metadata.prompt_fingerprint` に残し、作り直しのときに今の指紋と比べる。
同じなら結果も同じ、違えば別の注文。

この仕組みより前に失敗した行は指紋を持たない。判断がつかないので通す。
止めると直しようのないカードが残るし、通してもその1回で指紋が残り、次からは正しく判断できる。

## ついでに直ったこと

失敗からの作り直しが、毎回キャッシュを迂回していた（`instructions.present?` が
空文字の指示でも真になっていたため）。同じ注文なら既にある絵で足りるので、
`force_generate` は「出来上がったものの作り直し」だけに絞った。

## 画面

`generation_retryable` を返し、直らない失敗では作り直しのボタンを押せないようにして、
何を変えればよいかを書く。押してから断られるより、押す前に分かるほうがよい。
