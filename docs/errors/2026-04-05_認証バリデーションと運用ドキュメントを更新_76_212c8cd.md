# fix: 認証バリデーションと運用ドキュメントを更新 (#76)

- 状態: 下書き
- 初回記録日: 2026-04-05
- 対象範囲: 認証

## 概要

- 認証エラー文言の吸収漏れを追加で修正し、運用ドキュメントも実態に合わせて更新した。
- 前コミットで整えた認証バリデーションの抜けを埋めつつ、ローカル確認手順や Git 運用ルールの記録を補強した修正である。

## 症状

- 一部の signup エラー文言がまだフロントで吸収されておらず、ユーザー向けの表示が揺れていた。
- あわせて、開発手順や運用ドキュメントに実運用とずれている箇所が残っていた。

## 発生条件

- backend が `Email is not an email` のような既存マッピング外の文言を返すと、フロントで生の英語や未統一の文言が出る状態だった。
- 認証まわりの実装修正が続いた一方で、運用ドキュメントの更新が追いついていない状態で差分が積み重なると起きやすい。

## 原因

- 直接原因は、frontend の `auth-errors.ts` に backend 文言の追加バリエーションが十分に登録されていなかったこと。
- もうひとつの原因は、実装変更時に更新すべき docs の範囲が固定されておらず、運用手順と実装の差分が残っていたこと。
- 根本原因は、認証まわりの修正をコードとテストだけで閉じやすく、ユーザー向け文言と運用 docs まで一緒に見る運用が弱かったこと。

## 修正内容

- コミット要約: `fix: 認証バリデーションと運用ドキュメントを更新 (#76)`
- `frontend/src/lib/auth-errors.ts` に認証エラー文言の追加マッピングを入れた。
- `frontend/test/auth-errors.test.mjs` を更新し、追加した文言変換の回帰を固定した。
- `docs/playbook/development.md`、`docs/ops.md`、`docs/decisions/git-workflow.md` を更新し、運用と実装のずれを補正した。
- `frontend/src/components/features/items/ItemList.tsx` は関連差分として微修正が入っているが、主題は認証文言と docs の整合である。

## 影響範囲

- 主な影響範囲は signup / login のエラー表示と、それを確認・運用する開発者向け docs。
- 認証 API 自体の成功失敗ロジックよりも、ユーザー向けメッセージ整形と運用整備に寄った修正である。

## 学び

- 認証の修正では、挙動だけでなくエラー文言の吸収漏れもレビュー対象に含めるべき。
- 実装と docs の更新を別タスクにするとズレやすいため、運用に直結する変更は同じ修正単位で更新する方が安全。

## 再発防止

- `frontend/test/auth-errors.test.mjs` で追加文言の回帰を固定した。
- `docs/playbook/development.md` と `docs/ops.md` を更新し、今後の確認導線を整えた。
- 詳細な認証回帰観点は後続の `docs/playbook/auth-regression-checklist.md` につながる判断材料になった。
