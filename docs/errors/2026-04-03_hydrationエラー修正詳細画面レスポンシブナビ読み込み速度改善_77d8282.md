# fix: hydrationエラー修正・詳細画面レスポンシブナビ・読み込み速度改善

- 状態: 下書き
- 初回記録日: 2026-04-03
- 対象範囲: フロントエンド

## 概要

- 認証ガードまわりの hydration mismatch と、詳細画面の操作性・読み込み効率を同時に改善した修正である。
- SSR とクライアント初期化のずれで起きる表示不整合を避けつつ、items 詳細画面のナビゲーションとキャッシュ利用を見直した。

## 症状

- 認証必須ページで hydration mismatch による警告や表示の不整合が起きうる状態だった。
- items 詳細画面では、モバイルでの前後移動が扱いづらく、一覧キャッシュがあっても不要な API 呼び出しが発生していた。

## 発生条件

- 認証状態を local storage から復元するタイミングと SSR 初期描画がずれると、`AuthGuard` で hydration mismatch が起こりやすかった。
- items 詳細画面を直接開く、または一覧から遷移したときに、`allIds` 管理とデータ取得が分散していて無駄な fetch が起きていた。
- モバイル表示では詳細画面ナビゲーションの配置が画面サイズに最適化されていなかった。

## 原因

- 直接原因は、`AuthGuard` の初期描画が hydration 前後で一致しない可能性を持っていたこと。
- もうひとつの原因は、items 詳細画面で「本体取得」「一覧 ID 管理」「ポーリング」の責務が十分に分離されておらず、キャッシュ活用も弱かったこと。
- 根本原因は、認証ストア hydration と詳細画面データ取得のライフサイクルを、UI 表示と一体で整理できていなかったこと。

## 修正内容

- コミット要約: `fix: hydrationエラー修正・詳細画面レスポンシブナビ・読み込み速度改善`
- `frontend/src/components/features/auth/AuthGuard.tsx` で SSR / クライアント初期描画をともに `false` から始め、hydration 完了後だけ認証判定するようにした。
- `frontend/src/stores/items.ts` を追加し、items 一覧キャッシュを Zustand に切り出した。
- `frontend/src/components/features/items/ItemList.tsx` でフェッチ後に items ストアへ書き込むようにした。
- `frontend/src/app/(app)/items/[id]/page.tsx` で effect を責務別に分離し、キャッシュがあるときは `getItems()` を避け、モバイル / デスクトップでナビゲーション配置を切り替えるようにした。

## 影響範囲

- 影響範囲は認証ガード配下の画面、items 一覧、items 詳細画面の表示と遷移。
- API 仕様変更はなく、主にフロントの表示安定性と操作性、読み込み効率に影響する修正である。

## 学び

- persistence を持つストアを SSR 配下で使うときは、hydration 前後で同じ初期描画を保証する設計が必要。
- 詳細画面は 1 つの effect に責務を寄せず、「本体取得」「一覧情報」「ポーリング」のように分解した方が後から壊れにくい。

## 再発防止

- `AuthGuard` に hydration 防止コメントを残し、同じパターンを再導入しにくくした。
- items キャッシュを `stores/items.ts` に集約し、一覧と詳細の責務分離を明確にした。
- 画面サイズごとのナビゲーション配置をコード上で分け、意図を読み取りやすくした。
