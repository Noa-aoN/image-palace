# Error Docs

`docs/errors/` は、発生した特定のエラーや不具合を 1 ファイル 1 事象で残すためのディレクトリです。

## 目的

- 同じ過ちを繰り返さないために、原因と再発防止を残す
- 再発時の判断を速くするために、確認箇所と影響範囲を残す
- 設計やレビューの学びを資産化する
- いつ、何が起きて、どう対応したかのログを残す

## 置くもの

- 実際に発生したエラー
- ユーザー報告やレビュー指摘で発覚した不具合
- 修正済みだが、再発時に切り分けが必要な事象

## 置かないもの

- 日報や雑多なメモ
- 横断的な運用手順
- 未発生の一般論だけの注意書き

横断的な手順やチェックリストは `docs/playbook/` に置きます。

## 位置づけ

`docs/errors/` は、単なる障害メモではなく、以下を兼ねる記録です。

- 障害の事例集
- 再発防止ログ
- 設計とレビューの学び

個別事象は `docs/errors/` に残し、横断的な手順やチェックリストは `docs/playbook/` に残します。

## ファイル命名

推奨形式:

```text
YYYY-MM-DD_<topic>.md
```

例:

- `2026-04-06_confirm_success_url未指定でメール登録に失敗.md`
- `2026-04-06_Email_is_not_an_emailがそのまま表示された.md`

自動生成スクリプトを使う場合は、重複を避けるために末尾にコミットハッシュ付きで出力されます。
内容を整えたあとに、必要なら読みやすい名前へ変更してください。

## テンプレート

新規作成時は `docs/errors/_template.md` をベースにします。

最低限、以下は埋めてください。

- 状態
- 初回記録日
- 対象範囲
- 概要
- 症状
- 発生条件
- 原因
- 修正内容
- 学び
- 再発防止
- 関連テスト
- 関連コミットまたは PR

## 自動ドラフト生成

最近の `fix:` コミットからドラフトを起こす場合は、以下を使います。

```bash
./scripts/generate_error_docs.sh
./scripts/generate_error_docs.sh --recent 3
./scripts/generate_error_docs.sh b61002c 033f709
```

このスクリプトは次を自動で埋めます。

- 対象コミット
- 変更ファイル
- 日本語のメタ情報
- 日本語の基本見出し
- Gemini による本文ドラフト

## AI による自動調査・本文生成

`generate_error_docs.sh` は `GEMINI_API_KEY` を使って Gemini API を呼び出し、以下をもとに本文ドラフトまで生成します。

- コミット差分
- 変更ファイル
- 関連テスト
- 関連 docs
- 既存の `docs/errors/` にある近い事例

Claude Code の `error-docs` skill は、このスクリプトを呼ぶ入口として使います。

補助的に、以下のコンテキスト収集スクリプトも使えます。

```bash
./scripts/collect_error_doc_context.sh <commit>
```

ただし、概要、原因、学び、再発防止の内容は最終的に人が確認して整えてください。

## Skill から呼ぶ

Claude Code では `error-docs` skill から同じスクリプトを呼べます。

```text
/error-docs
/error-docs --recent 3
/error-docs b61002c
```
