# ImagePalace 機能仕様書

> 最終更新: 2026-04-20

---

## サービス概要

テキスト中心の学習に違和感を持つビジュアルシンカーのための、イメージ特化型学習支援サービス。
単語や概念をAI生成画像に変換し、視覚的に記憶しやすいカード形式で管理・想起する。

---

## 用語集

| 用語 | 定義 |
|-----|------|
| アイテム（item） | 単語 + AI生成画像 のペア。学習の最小単位。旧称「カード」「object」は廃止済み |
| item_type | アイテムの種別（現在は `term` のみ。seed 必須） |
| shared_media | 同一単語の画像キャッシュ。`normalized_prompt` を UNIQUE キーに保持 |
| normalized_prompt | キャッシュキー用に正規化した単語（`NormalizePromptService` が生成） |
| 生成ステータス | `pending` → `processing` → `completed` / `failed` |
| metadata | `item.metadata` にエラーコード・メッセージを保存。`shared_media.metadata` に `revised_prompt` を保存 |
| Solid Queue | Rails 8 標準の非同期ジョブ実行基盤。PostgreSQL をキューに使用（Redis 不要） |
| shared_brief | 単語ごとの説明文キャッシュ。「単語→説明文→情景」の2段階生成の中間物 |
| クレジット | 生成の可否を決める残高。**1クレジット = 画像1枚**。固定の月間枚数上限は無い |
| 生成枠 | 無料は登録時のお試し 3cr + 毎月 1cr（`Billing::Catalog`）。有料はサブスク + 買い切り |

## 画像生成フロー（概要）

1. ユーザーが単語を入力し「生成」ボタンを押す
2. `Items::CreateService` がクレジット残高を確認する（1クレジット = 1枚）
3. `NormalizePromptService` でキャッシュキーを生成
4. `shared_media` テーブルで `normalized_prompt` キャッシュを確認
   - **キャッシュあり** → 即座にアイテムを返す（API呼び出しなし）
   - **キャッシュなし** → `GenerateImageJob` をキューに積み、`pending` 状態のアイテムを返す
5. `GenerateImageJob` が OpenAI gpt-image-1 API を呼び出す（失敗時は自動リトライ）
6. 生成された画像を Cloudflare R2 に保存し、ステータスを `completed` に更新
7. フロントエンドのポーリングが完了を検知し、画像を表示する

## 制約・非機能要件

| 項目 | 内容 |
|-----|------|
| 生成の可否 | クレジット残高で決まる（`Items::CreateService` で検証）。固定の月間枚数上限は無い |
| 生成コスト | `shared_media` / `shared_briefs` キャッシュで OpenAI API コストを抑制 |
| 原価の把握 | 画像は `image_usages`（キャッシュ命中も記録）、文章は `ai_usages` に残す |
| 生成待機時間 | 非同期処理のため、生成完了まで数秒〜数十秒かかる |
| 自動リトライ | 最大3回（指数バックオフ）。全消費後に `failed` へ |
| データ所有 | アイテムは作成ユーザーのみアクセス可能（`current_user.items.find(id)` で検証） |
| 画像配信 | R2 直配信禁止。CDN（`CDN_BASE_URL`）経由のみ |
| API キー | OpenAI API キーはバックエンドのみに設定。フロントから直接呼び出し禁止 |
| OAuthセキュリティ | トークンはクエリパラメータ（`?`）ではなくURLフラグメント（`#`）で渡す |
| CORS | 許可オリジンは `CORS_ORIGINS` 環境変数で管理。本番では `*` 禁止 |
