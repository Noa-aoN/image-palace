## 対象

$ARGUMENTS が指定されている場合はそのファイルのみ確認する。
指定がない場合は以下のすべてを対象とする:

- `docs/architecture.md`
- `docs/spec.md`
- `docs/decisions/` 以下のすべての `.md`
- `docs/playbook/` 以下のすべての `.md`
- `CLAUDE.md`
- `.claude/rules/` 以下のすべての `.md`

## レビュー手順

### 1. 現在のコードベース状態を把握する

以下を確認してドキュメントとの照合に使う:

- ディレクトリ構成: `find . -type f -name "*.rb" -o -name "*.tsx" | head -50`
- 環境変数ファイル: `.env.development`, `.env.production`, `.env.local.example`
- ポート設定: `docker-compose.yml` や `next.config.ts`
- DB スキーマ: `backend/db/schema.rb`（テーブル名の確認）

### 2. image-palace 固有チェック項目

ドキュメントを読みながら以下を必ずチェックする:

**ポート番号**
- フロントエンド（Next.js）: `localhost:3000`
- バックエンド（Rails）: `localhost:3001`
- 逆になっている記述はないか

**用語**
- `items` が正しいテーブル名
- `cards` / `objects` / `card_sets` という記述が残っていないか

**デプロイ先**
- フロントエンド: Cloudflare Workers（`Cloudflare Pages` は誤り）
- バックエンド: Fly.io
- DB: Neon (PostgreSQL)

**非同期処理**
- Solid Queue（Redis 不要）が正しい
- Redis をキューに使う記述が残っていないか

**環境変数管理（フロントエンド）**
- `.env.development`（コミットする）: 開発環境の非シークレット設定
- `.env.production`（コミットする）: 本番環境の非シークレット設定
- `.env.local`（コミットしない）: シークレット専用

**decisions/ の状態**
- 「未実装」「実装予定」として書かれている内容が、実は実装済みでないか
- 過去形で書かれるべき内容が未来形になっていないか

**CLAUDE.md / rules/ の整合性**
- コマンド例が実際の構成と合っているか
- ディレクトリパスが実際の構成と合っているか

### 3. 出力フォーマット

```markdown
## ドキュメントレビュー結果

対象: [ファイル一覧]

---

### 🔴 要修正（情報が古い・間違い）
- `ファイルパス:行番号` — 問題の説明 → 修正案

### 🟡 要確認（コードと一致しているか不明）
- `ファイルパス` — 確認が必要な理由

### 🟢 提案（より良くできる点）
- 提案内容

### ✅ 問題なし
問題のなかったファイル・セクションを列挙

---

## まとめ

修正が必要な箇所: X 件（🔴 A件 / 🟡 B件）

修正を実施しますか？
- 「はい」→ 順番に修正する
- 「特定のファイルだけ」→ 指定してください
- 「いいえ」→ レビュー完了
```

修正を実施する場合は、ファイルごとに Edit ツールで修正し、変更内容を簡潔に報告する。
